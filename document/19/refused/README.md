# Refused documents

Each folder here holds one document that the app refuses, and a `README.md` naming the one rule it
breaks. Every document is otherwise valid: with that one fault removed, it opens. The app refuses every
one of them. Another reader MAY be more lenient ([Conformance](../README.md#conformance)), but a
writer MUST NOT produce documents like these.

The messages are the app's English messages, quoted as examples. The app shows them in the Mac's
language where a translation exists. Programs MUST NOT match on their text (see
[Messages quoted in this specification](../README.md#messages-quoted-in-this-specification)).
Identifiers inside a message are the document's own.

"Schema" says whether the [JSON Schemas](../schemas/), with the schemas of the
[complex-shape catalogue](../complex-shapes/README.md), can catch the fault on their own. "No" means a
program must check the rule itself.

## Before opening one

Git does not keep empty folders, so each document here that has no artwork is stored without its empty
`assets/` folder. A reader accepts that and treats the folder as empty
([Package rules](../README.md#package-rules)), so each case is refused for its own rule as stored. The
documents about assets have their `assets/` folder.

## How these were checked

Every document here was opened with the reading code of SimpleDiagrams 5.2, as stored. Each was refused
with the message shown, and each case whose message names only the file was opened again with its one
fault repaired as its README says. The four described-only faults were checked the same way.
